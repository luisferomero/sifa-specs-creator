# Application Interface Contract

**Version**: 0.1.0 (design)  
**Scope**: Spanish browser UI, typed Next.js Server Actions, and narrow route handlers. This is a first-party application contract, not a promise of a public REST API. All commands use [data-model.md](../data-model.md).

## Common types and guarantees

- ID: UUID generated by the application/database; actor comes from the verified session.
- ReviewToken: { featureId, editRevision, sourceRevision, currentSetRevisionId: ID|null, understandingId: ID|null }.
- Mutation: { commandId: ID, projectId: ID, featureId: ID, expected: ReviewToken, payload }. Creation uses projectId/moduleId and commandId without an existing token.
- Success: { ok: true, data, token, commandId }. AI operations also include runId/status.
- Error: { ok: false, code, messageEs, fieldErrors?, currentToken?, retryable, commandId }. No success indicator precedes commit.
- Codes: UNAUTHENTICATED, NOT_FOUND, VALIDATION_FAILED, CONFLICT, PRECONDITION_FAILED, AI_UNAVAILABLE, AI_INVALID_OUTPUT, RUNNING, PROCESSING_FAILED, RATE_LIMITED.
- Unauthorized/cross-Project/deleted Feature lookups return the same NOT_FOUND without content or existence details. Authentication failure returns UNAUTHENTICATED. HTTP equivalents are 401, 404, 422, 409, 409, 503, 502, 202, 422, 429.
- Same commandId and fingerprint cannot create duplicate effects; same ID with different payload fails. Every retry, including receipt replay, rechecks current membership and deletion. Return result identities/status and current permitted state, not an unguarded cached sensitive response.
- Server Actions validate same-origin requests; HTTP mutations enforce Origin/CSRF protections. Private responses use no-store and are excluded from shared caches.
- Client-supplied projectId, moduleId, featureId, screenId, sourceId, optionId, requirementId, setRevisionId, and approvalId are all checked for ownership. Being a member of two Projects does not permit linking their records.
- On CONFLICT preserve the user's editor state in memory; show their unsaved text next to fresh saved content. Only an explicit reconciliation submits a new command with a fresh token. Browser reload is not an autosave guarantee; warn before discarding unsaved edits. Persisted partial Drafts survive reopening.

Example conflict copy: "Otra persona guardó cambios. Conservamos tus cambios sin guardar. Revisa la versión actual antes de volver a guardar."

## UI flow

| View | Spanish behavior | Exit condition |
|---|---|---|
| Sign in / Project | Sign in, session recovery, only authorized Projects and Modules | Verified identity and current membership |
| Feature list | Create/resume, distinguish Borrador / Necesita revisión / Aprobado; confirm soft deletion | Active Feature selected |
| Intake and Screens | Minimal seven intake topics; save partial work; explicit unknown choices; labeled multi-Screen sources | Required intake accepted before analysis |
| Analysis/interview | Display processing notice before first analysis; pending/retry feedback; one question, <=4 choices, optional context, "No lo sé"/skip | No material gap or seven slots reached |
| Understanding | Spanish purpose/users/workflow/rules/uncertainties; original sources inspectable; correct then confirm | Fresh confirmed summary |
| Requirements review | Six categories, evidence panel, linked dependencies, behavior intent, edit/reject; current vs proposed replacement comparison | Reviewed supported assertions; unresolved items visible |
| Approval/export | Separate approval control, full-set confirmation, explicit gap acknowledgement, identified approver/time; download only when currently Approved | Exact approved Markdown |
| Conflict/recovery | Preserve editor state, compare with latest, explicitly reconcile; run status survives lost response | New valid token or retryable failure |

All participant-facing labels/messages are Spanish, including authentication errors, upload progress, provider failure, and deletion confirmation. Use semantic labels, keyboard-operable controls, visible focus, and an announced pending/error state. Do not require a facilitator for any view.

Behavior labels: CURRENT = "Comportamiento actual de SIFA"; DESIRED = "Comportamiento deseado"; BOTH = "Ambos"; UNKNOWN = "Desconocido / Requiere decisión".

## Server Action operations

Each Feature mutation carries the common Mutation envelope unless otherwise stated.

| Operation | Payload / preconditions | Result and effects |
|---|---|---|
| listProjects / listModules / listFeatures / getFeature | Membership; paginated stable cursor for lists; active ancestor | Only authorized active content; getFeature returns token, current understanding/set, proposal summaries, approval and outstanding question |
| createFeature | moduleId, partial intake: name/users/purpose/workflow/rules and explicit users/rules statuses | DRAFT and token; source rows for supplied text |
| saveIntake | Partial changed fields; selected Module must be in Project | Preserve originals, append Sources; advance revisions; invalidate approval if needed |
| saveScreen | screenId? and label/position; local evidence identity remains distinct | Stable Screen ID; source-affecting changes advance revisions |
| detachScreen / detachAttachment | Owned ID and explicit confirmation | Detach from current evidence, retain original accepted bytes/records; invalidate approval |
| prepareUpload | screenId, filename, declared MIME/bytes | Intent ID, opaque Storage path, expiry; not an accepted Source and no business revision change |
| finalizeUpload | intentId, expected token; server reads/decodes bytes | Attachment/source IDs and new token; failure/conflict preserves saved content and does not publish evidence |
| recordAiNotice | noticeVersion shown to current participant/Project | Receipt; required before first analyze request; no business approval |
| answerQuestion | questionId, disposition ANSWERED/UNKNOWN/SKIPPED, optionIds[], contextEs? | Persist answer/source; source/edit revision advances; question retains ordinal |
| confirmUnderstanding | understandingId, optional corrected purpose/users/workflow/rules/uncertainties, inspected source revision | Correction + Source + resulting summary confirmation atomically; new token |
| reviseRequirements | current setRevisionId; explicit item text/intent/disposition/evidence/link changes | Immutable new revision plus human correction Sources; NEEDS_REVIEW |
| resolveOpenQuestion | questionId, supplied human answer or captured sourceId; affected-item decisions | Resolution Source and new current set revision; unsupported dependents remain uncertain until explicitly reviewed |
| acceptReplacement | proposedSetRevisionId and compared base current set/source/understanding IDs | Only fresh, reviewed replacement becomes current; NEEDS_REVIEW; clear current approval/receipt |
| rejectReplacement | proposedSetRevisionId | Mark proposal rejected; current set, human edits and approval unchanged unless independently invalidated |
| reconcileReview | current setRevisionId, inspected source revision, reviewed item IDs with support dispositions, unresolved gap IDs | Immutable review receipt for this token; rejects claims marked included without actual support |
| approveRequirements | receiptId, currentSetRevisionId, exact acknowledgedOpenQuestionIds, expected token | Immutable approval + current approval ID; only explicit human action yields APPROVED |
| softDeleteFeature | confirmed=true, expected token | Immediate tombstone, retained children/files; ordinary access ends |
| getAiRun | runId, projectId, featureId; read-only | Authorized saved status/result IDs or retryable expired lease; no domain writes from polling |

Intake analysis validation checks presence independently from Draft-save validation. Nonblank users/rules text or explicit UNKNOWN is accepted; NONE_KNOWN is valid for rules. A screenshot is accepted only after finalizeUpload commits. Do not add extra stakeholder intake fields.

Question answers validate option ownership and SINGLE/MULTIPLE cardinality. UNKNOWN/SKIPPED requires zero selected options; optional context is retained without inventing a selected answer. A still-relevant unanswered outstanding question prevents a second one from appearing, even at ordinal seven. If newly captured sources resolve its gap, retire it as RESOLVED_BY_SOURCE without resetting its counted ordinal, then stop or continue only for remaining material gaps.

Understanding corrections cannot conceal contradictory Sources. Regeneration takes the latest applicable human corrections as evidence. Proposed replacement acceptance does not delete retained sources, correction provenance, or previous set revisions.

## Direct Storage protocol

1. prepareUpload authorizes current membership/active Feature and creates an expiring intent. Declared type/size preflight is not final validation.
2. Use Supabase's authenticated resumable upload with the user's JWT and no upsert. INSERT policy permits only that uploader's exact pending path and active membership/Feature. Client UPDATE/DELETE are denied; incomplete objects are not participant-readable.
3. finalizeUpload accepts metadata only. Server reads bytes with narrow privileged access, validates full decode, hashes originals, then rechecks authorization/token in its publication transaction.
4. Authenticated Storage download requires an accepted Attachment + active Feature + current live membership. Fetch Blob bytes directly from Storage, render a temporary object URL, release on navigation/logout, and avoid persistent/private-content caching. No signed/public download URLs or public optimizer.
5. Expired, rejected, or conflicted intents never appear as shared Sources. Retrying finalization cannot overwrite accepted objects or publish twice.
6. Revocation/soft deletion denies future Storage requests even with an old valid user JWT. Bytes already received before revocation cannot be recalled.

Bucket and validation limit: PNG/JPEG, max 10,000,000 bytes inclusive. Supabase TUS chunk configuration follows the official protocol; chunk size is independent of the per-file cap.

## Bounded AI HTTP endpoints

Prefix: /api/projects/{projectId}/features/{featureId}/ai

| Method/path | Request | Success |
|---|---|---|
| POST /analyze | commandId, expected token; sufficient intake and notice receipt | 200 run/result IDs, updated summary/token, gaps |
| POST /question | commandId, expected token; existing gap analysis | 200 outstanding question or stopped reason; may return existing slot without a provider call |
| POST /generate | commandId, expected token; fresh confirmed understanding | 201 current initial set or separate proposed replacement; never approval |

Operations persist a run before calling the provider and return only after validated commit, bounded failure, or an existing in-progress response (202 + runId). A lost connection is resolved by getAiRun. Retrying an expired/failed attempt uses a new commandId after status reconciliation. Clients never call OpenAI. See [ai-service.md](./ai-service.md).

## Export route

GET /api/projects/{projectId}/features/{featureId}/export?approvalId={id}&editRevision={n}&sourceRevision={n}&setRevisionId={id}

Require the viewed current approval and token; do not silently download a newer approval. Return 200 text/markdown; charset=utf-8 and attachment disposition, or the common error envelope. It makes no business content changes. Full format and concurrency rules: [markdown-export.md](./markdown-export.md).

## Excluded interfaces

No end-user restore/purge, Project/member administration, GitHub publishing, Spec Kit execution, automatic code generation, or unauthenticated source sharing endpoint.
